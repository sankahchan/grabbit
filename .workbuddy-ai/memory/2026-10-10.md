## Build verification approach (important — reuse this)
`xcodebuild` cannot run here: the sandbox blocks its nested sandboxing
("sandbox-exec: sandbox_apply: Operation not permitted") even with
`dangerouslyDisableSandbox: true`. Instead typecheck/link with `swiftc`
directly, bypassing its own sandbox:

```
SDK=/Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX27.0.sdk
find Grabbit -name '*.swift' -print0 | xargs -0 /usr/bin/swiftc -typecheck -disable-sandbox \
  -sdk "$SDK" -target arm64-apple-macosx14.0 \
  -import-objc-header Grabbit/Engine/ALPNPin.h \
  -F build/Build/Products/Release
```
- For a full **link**, also pass `Grabbit/Engine/ALPNPin.m` (ObjC) or you get
  "Undefined symbols: _GrabbitPinALPNToHTTP11". Result: ~13.5 MB binary, 0 errors.
- Two `ld: warning`s (CoreAudioTypes not found; SwiftUICore not an allowed client)
  are **harness artifacts**, not project issues — Xcode links them normally.
- `find ... -print0 | xargs -0` is required (zsh does not word-split the file list).
- Tests can't be built in this harness ("no such module XCTest" / "not compiled
  for testing") — a harness limitation, not a project defect.

## Bugs fixed this session (all verified, project now 0 errors / 0 warnings)
1. `Engine/TorrentEngine.swift` — data-loss bug in `remove(_:deleteData:)`: the
   no-daemon-entry branch deleted the whole shared `savePath`. Now only deletes
   the torrent's own file/folder via new `deleteOwnedData(name:savePath:)`, with a
   `dir.path + "/"` prefix guard (was a bare `hasPrefix` that matched siblings
   like `Downloads2` for `Downloads`). Also fixed the sibling guard in
   `deleteData(gid:saveDir:)`.
2. `Engine/MediaEngine.swift` — `notifyMediaFailure` used the wrong flag
   (`showCompletionToast` → `showFailureToast`); `downloadStream` preset match
   changed from label `== "Best"` to stable `id == "best"` and gained a
   `presetID: String? = nil` override param; removed an unnecessary `await` on the
   now-synchronous `notifyMediaFailure` (was a compiler warning).
3. `Engine/SchedulerStore.swift` — `.speedLimit` schedule action now also calls
   `torrentEngine.applySpeedLimit()` (previously only the download engine synced).
4. `UI/Views/TaskDetailsSheet.swift` — "Restart from beginning" called only
   `cancel()` (left the task `.queued` but not running); now `cancel()` + `resume()`.
5. `UI/Views/DownloadsStatsHeader.swift` — "today" stats used
   `calendar.isDateInToday(...)`, ignoring the injected `now` param; now
   `calendar.isDate(..., inSameDayAs: now)`.
6. `UI/Views/LinkGrabberView.swift` — removed a **dead** path: a `DetectedMedia`
   struct + `@State detected` array that was never assigned, plus the unreachable
   "browser media" section and `grab(_:)` fn. Also dropped the now-unused
   `engine`/`settings` environment properties.
7. `UI/Views/AddDownloadSheet.swift` — the quality/format pickers were UI-only
   ("will be passed to the extractor once it lands"). Now wired: media sites
   (YouTube/X/TikTok/Instagram/Telegram) and `.m3u8`/`.mpd` route to
   `MediaEngine.downloadStream(presetID:)` (preset id = quality, or "audio"),
   switch the sidebar to the Media tab, and honour the per-task speed cap;
   everything else keeps the segmented direct-engine path. The controls are now
   only shown for media sites (quality hidden in audio mode) so no dead control
   is ever displayed.

## Reviewed, NOT changed (benign — do not "fix" these)
- `Engine/RSSMonitor.stop()` is defined but never called. The timer is a single
  repeating `Timer` with `[weak self]` on the app-lifetime `@State` monitor;
  `start()` already invalidates before rescheduling. Wiring `stop()` to window
  `onDisappear` would be a **regression**: tray mode hides the window while the
  app keeps running and must keep polling RSS. Left as-is.
